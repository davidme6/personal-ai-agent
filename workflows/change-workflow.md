# 改造与编程工作流：G0–G6

改结构、写代码、批量改文件、迁移同步、装工具，都按这七步走。先复制 `templates/task-card.md` 到 `.personal/logs/task-cards/YYYY-MM-DD_主题.md`，每完成一步勾一项。

| 步骤 | 做什么 | 完成的标志 |
|---|---|---|
| G0 接手 | 读 AGENTS.md、current-state、相关项目入口；私有仓模式先 `sync.py pull` | 能说出当前状态和本次范围 |
| G1 探查 | 读现有代码、资料、日志；查有没有别的窗口或 AI 正在改同一批文件（`git status`、修改时间、当天任务卡） | 知道要改哪里、会影响什么 |
| G2 方案与备份 | 说明方案、影响和不做的部分；覆盖或移动前先备份（Git 能回退的可以不另备份） | 用户认可方案；备份位置写进任务卡 |
| G3 执行 | 按方案改，只改该改的 | 改动完成 |
| G4 验证 | 跑测试、实际运行一次；没验证到的写明；非小改动找另一个 AI 或独立子代理审 | 验证结果原文写进工作日志 |
| G5 记录 | 工作日志、current-state、未闭环事项 | 三处都写了任务标记 |
| G6 提交 | `python tools/sync.py push --task-card <任务卡> --message "说明" 文件…` | 推送后本机和远端提交一致 |

几条硬规矩：

- 合并、迁移只增不删；用户数据不删除。
- 本机和云端都改过的文件，自动三方合并；合不上的保留本机版本并列为分叉，交给用户定。
- 同一动作失败两次换办法。
- 设备上、云端没实测的单列，不能拿本机通过代替。

`.personal/agent.json` 里 `require_task_card` 设为 `true` 后，`tools/workflow_gate.py` 会在每次提交前核对：任务卡 G0–G5 都勾上、验证结果为“通过”、工作日志含任务标记和验证结果、current-state 含任务标记。

# 日终复盘

一天结束时，把这一天在所有窗口、所有 AI 里做的事汇总一遍，更新状态，沉淀下能留下来的东西，定好明天第一件事。目的是第二天不管打开哪个 AI，都能直接接上。

和 [session-end.md](session-end.md) 的分工：

| | 管什么 | 什么时候 |
|---|---|---|
| `session-end.md` | 单次会话的收尾：这一个窗口的原文、工作日志、状态 | 每次会话结束 |
| `daily-review.md`（本文） | 一整天的汇总：跨窗口、跨 AI、跨项目，查漏、结算、定明天 | 一天一次，一般在最后一个会话里做 |

本文不重复 session-end 的逐项步骤；当前会话还没收尾的，先按 session-end 收完，再做下面的事。

## 什么时候做

- 用户说“复盘一下今天”“日终复盘”“今天的总结”；
- 用户说“今天到这”时，按 `AGENTS.md` 先做“归档”；如果这是当天最后一个会话，顺带问一句要不要做日终复盘，不要自作主张。

## 输入

- 今天的工作日志 `.personal/logs/work-logs/`、任务卡 `.personal/logs/task-cards/`
- 今天的对话原文（`.personal/logs/chat-exports/00_index.md` 里今天的那几行）
- 变更留痕：`python tools/trace_changes.py report --date YYYY-MM-DD`
- `.personal/current-state.md`、`.personal/memory/open-loops.md`、今天动过的项目的 `STATE.md`

## 步骤

### 1. 先查漏

- 跑 `python tools/refresh.py`，把本机所有 AI 今天的对话导出齐（脚本幂等，已经导出过的会跳过）。
- 看 `trace_changes.py report` 标出的“有改动却没有工作日志”的地方，补上对应的工作日志；补不出原因的写“原因待补”，不猜。
- 网页版 AI 今天聊过、但还没取回的，按 [网页版 AI 归档](../docs/web-ai-archive.md) 取回。

### 2. 汇总今天做了什么

按项目（或按模式）列：做了什么、推进到哪、证据在哪个文件。没有实质进展的项目如实写“无进展”，不凑内容。

### 3. 结算状态和未闭环

- `current-state.md`：改成今天收工时的真实状态。只改自己负责的部分，不抹掉别人写的。
- `open-loops.md`：新冒出来的事加进去，做完的改成 `status: closed`；每条都要有下一步、卡点、source。
- 每个今天动过的项目：`STATE.md` 里的“下一步”要明确到动作。
- 销售类项目：每个还在跟的客户都要有“下一步 + 日期”，过期没跟的列出来（见 [销售模式](../modes/03-sales.md)）。
- 学习类项目：更新掌握情况（没有新证据不往上调），重排复习队列，列出明天到期的复习项（见 [学习模式](../modes/01-learning.md)）。

### 4. 沉淀能留下来的

| 内容 | 去哪 |
|---|---|
| 今天核实过来源的知识 | `.personal/knowledge/verified/` |
| 有用但还没核实的 | `.personal/knowledge/unverified/` |
| 用户新定的规矩、偏好变化、稳定的决定 | `.personal/memory/`（追加，带元数据，见 [记忆系统](../docs/memory-system.md)） |
| 同一类错误出现两次以上 | `.personal/memory/` 里的错误模式条目 |
| 可复用的方法、模板、案例 | 对应项目目录，或 `skill/` |

原始聊天不直接当知识，按 [知识源与验证](../docs/knowledge-sources.md) 的规则走。

### 5. 定明天第一件事

只定一件，具体到动作和文件，例如“打开 `.personal/projects/示例项目/STATE.md`，把第 2 步的测试跑通”。写在 `current-state.md` 的“Next actions”最上面。

### 6. 写当天交接

写 `.personal/handoff/YYYY-MM-DD.md`（模板 `templates/handoff.md`）：今天停在哪、已确认的事实、明天第一件事、需要用户确认的事。当天已经有交接的，接着续写，写明新的写入时间。

### 7. 告诉用户

一小段话：今日小结、明天第一件事、待用户确认的事、还有哪些没上传到云端。

## 权限

- 全程只写本机的状态和日志文件，属于“直接做”，但要可追溯。
- 对外发消息、删除、把客户推进到成交或输单这类关键变更，复盘里不做，只列成待确认项。
- 上传不上传，按用户说的是“归档”还是“归档本地云端”来（见 `AGENTS.md` 第四节）。

## 异常

- 今天没有实质进展：如实写，不编进展。
- 信息不够判断掌握程度或客户阶段：标“待确认”，不臆断。
- 原文和记忆对不上：以原文为准，在交接里写明哪里对不上。

# 云端写入护栏

只管“存”，不管“读”。读在线文档、下载文件照常做；下面的规矩管的是往云端写东西：

- 上传文件、同步资料库；
- 新建或导入在线文档、表格、幻灯片、白板；
- 在云盘里移动、复制文件；
- 往在线表格、多维表格写记录。

## 为什么要有这道护栏

- **存错了地方，往往收不回来。** 很多企业版、团队版云盘的管理员能在后台搜到成员的文件、把所有权转给别人，删掉的也能恢复。东西存进了不是你自己的空间，就归那个空间管了，自己删掉并不等于没发生过。
- **账号容易认错。** 同一个人常常有几个账号（个人的、公司的、不同团队的），显示的名字可能一模一样；同一台电脑上不同的工具、不同的窗口，登录的也可能不是同一个账号。只看名字判断，迟早存错。
- **AI 的记忆不可靠。** “上次就是存这里的”不能作为依据，每次都要以当场查到的为准。

## 规则

1. **先查身份，查不出就不存。** 存之前查清当前工具登录的是哪个账号、哪个团队空间（租户）。认账号用配置名、空间名、账号 ID 这类唯一的东西，不凭显示名字。查不出来，或者查到的不是用户要存的那个，就停下，告诉用户“现在登录的是别的账号，没传”。
2. **再查位置。** 要存进哪个文件夹：名字、路径或链接、所有者是谁，都要当场查出来，不凭记忆、不猜。
3. **原样摆给用户，第一次必须确认。** 把查到的账号、空间、文件夹、要做的事（传几个文件、举几个例子、会不会覆盖什么）原样告诉用户，问“存吗？”。用户明确说“是”（或同样意思）才动手；没回、回得含糊、说“先别”，都不存。
4. **同一账号、同一目标、同一范围内不再反复问。** 用户确认过之后，这一件事里的续传、失败重试、收尾补传直接做。下面任何一项变了，就重新查、重新问：
   - 换了账号或空间；
   - 换了目标文件夹；
   - 范围变了（多了新的目录、改了排除规则、要做的事明显超出用户看过的计划）。

   用户说暂停或取消，立刻停，不在后台自己恢复。这件事做完，这次的确认就结束了，不能拿它去做下一件事。
5. **从不改分享权限。** 不开链接分享、不加协作者、不转所有者。新传的东西默认不对外，要对外由用户自己开。
6. **存错了马上说，不要自己删了了事。** 告诉用户：存了什么、存到了哪个账号哪个位置、链接是什么。删不删、怎么删由用户定，删除本身也要用户同意。
7. **哪些永远不传。** `.personal/private/`、`.device/`（包括 `.device/secrets/` 里的凭据）、`.local/`，以及 `.personal/agent.json` 里 `local_only` 登记的路径。脚本已经挡住了它们，你也不要手动去传。
8. **脚本报什么就照实说。** 同步脚本报了冲突、列出了“云端删了”或“云端新加的”，停下来把原文告诉用户，不绕开脚本手动覆盖，也不要把“脚本跑完了”说成“没有冲突”。

## 项目文件上云：只走脚本

不绕开脚本直接调命令行传项目文件（例如直接用 `lark-cli` 的上传命令、`rclone copy` / `rclone sync`）。脚本会先认账号、先出计划、按上次同步的基线比差异，冲突两份都留；手动传没有这些保护。

### 飞书：`tools/feishu_sync.py`

```bash
python tools/feishu_sync.py whoami                   # 1. 看命令行现在登录的是谁
python tools/feishu_sync.py plan                     # 2. 出计划：账号、文件夹、要做的事、计划编号，不动手
python tools/feishu_sync.py sync --approve <计划编号>  # 4. 用户确认之后才执行
python tools/feishu_sync.py verify                   # 5. 只读核对结果
```

第 3 步是你做的：把 `whoami` 和 `plan` 的输出原文贴给用户，等用户明确说“是”。用户没确认过的计划编号，不带去执行。

- `resolve <路径…>` 用来处理冲突（以本机这份为准，或允许重新上传云端已删的），只在用户对这几个文件逐个做了决定之后才用，不拿它批量绕过冲突。
- 定时任务里的 `sync --scheduled` 只有用户事先在设置里把开关打开才会执行，而且只做没有冲突的动作；这是用户提前给的授权，不要为了让它跑起来替用户去改开关。

### 其他云盘（Google Drive、OneDrive、WebDAV 等）：`tools/cloud_sync.py`

```bash
python tools/cloud_sync.py init         # 第一次：先预览，不改任何东西
python tools/cloud_sync.py init --yes   # 第一次：建立基线（用户确认后）
python tools/cloud_sync.py plan         # 之后每次：预览本机目录 ⇄ 远端会发生什么
python tools/cloud_sync.py run          # 之后：正式同步
```

`plan` 只显示远端名（`.personal/agent.json` 里的 `cloud.remote`），不显示是哪个账号。远端背后的账号是配置 rclone 时登录的那个；拿不准时，可以用 `rclone lsd <远端名>:` 看看顶层文件夹是不是用户认得的那几个，或者请用户在网盘网页端核对。不要把 rclone 配置文件里的令牌贴进对话。

## 不走脚本的时候

用户要你新建一份在线文档、往一个在线表格写记录，或者明确要存到某个别的账号，这时没有脚本替你把关，自己照着做：

1. 查身份：当前工具登录的是哪个账号、哪个空间。
2. 查位置：要存进的文件夹或表格叫什么、链接、所有者。
3. 把账号、位置、要存的东西原样摆给用户，等用户明确说“是”。同一件事里后续的写入不用再问，账号或位置变了再问。
4. 存完把链接给用户。

## 给别的 AI 的一段话

这个 Skill 只在本项目里有效。换一个窗口、换一家 AI，或者不在本项目里干活时，把下面这段放进那家 AI 的自定义指令或全局规则里兜底：

```text
【往云端存东西之前】
1. 存之前先查清当前登录的账号、团队空间和要存进的文件夹（名字、链接、所有者），以当场查到的为准，不凭记忆、不凭显示名字。
2. 第一次往某个账号或位置存，把查到的真实去处原样告诉我，我明确说“是”才存；同一账号、同一位置、同一范围内的续传和重试不用再问，账号、位置或范围变了再问。
3. 项目文件上云只用项目里的 tools/feishu_sync.py（飞书）或 tools/cloud_sync.py（其他云盘），先出计划给我看，不直接用命令行传。
4. 永远不改分享权限：不开链接分享、不加协作者、不转所有者。
5. 隐私目录、密钥、本机缓存永远不传。
6. 存错了马上告诉我存了什么、存到哪、链接是什么，不要自己删了了事。
```

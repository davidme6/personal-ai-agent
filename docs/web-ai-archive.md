# 网页版 AI 的对话归档

Claude Code、Codex 这类本机 AI 会在电脑上留下会话文件，`tools/chat_archive.py` 能直接逐字导出。网页版 ChatGPT、Claude 网页版、手机 App 没有本机会话文件，只能让它自己逐轮把原文写下来，存到它连得上的云盘，再由本机 AI 取回。

本文规定怎么写、存到哪、怎么续写、本机怎么接回来。最后附一段可以直接粘给网页版 AI 的提示词。

## 整体流程

```text
网页版 AI 逐轮写原文 → 副仓收件箱 inbox/<来源>/ → 本机 AI 归档时取回、核对
→ 并入 .personal/logs/chat-exports/web/<来源>/ → 总索引脚本收录 → 清掉收件箱里已取回的
```

## 存到哪、叫什么

- **位置**：副仓（如 Google Drive）里和本机同步的那个文件夹下的 `inbox/<来源>/`，例如 `inbox/ChatGPT网页版/`、`inbox/Claude网页版/`。
- **每场对话最多两份**：
  - 全文：`YYYY-MM-DD_<主题>_<来源>.md`
  - 单次索引（全文超过约 3000 字时才写）：`YYYY-MM-DD_<主题>_<来源>_INDEX.md`。必须是全文文件名去掉 `.md` 再加 `_INDEX`，总索引脚本按这个规则把两份配对。
- **存成 `.md` 或 `.txt` 普通文件**，不要存成云盘的在线文档（如 Google 文档）。在线文档同步到本机后往往不是能直接读的文本，脚本读不了，也进不了索引。
- 网页版 AI **不维护总索引**。总索引 `00_index.md` 全项目只有一份，由本机脚本按实际文件生成。

## 全文怎么写

开头写清来历，再逐轮写原文：

```markdown
# <主题>

- 来源平台：ChatGPT 网页版
- 会话链接：（有就写，没有写“待补”）
- 对话日期与时区：YYYY-MM-DD（时区）
- 归档写入时间：YYYY-MM-DD HH:mm（时区）
- 记录执行者：ChatGPT
- 完整性：尽可能完整版本；第 1–12 轮逐字，第 3 轮助手回复【原文不可取得】
- 本次写到：第 12 轮

## 第 1 轮

### 用户

（原文）

### 助手

（原文）
```

`- 来源平台：` 这一行会被总索引读出来，填在“平台”那一列。

要求：

- **用户的话逐字照抄**，口头语、重复、说错又改口的都留着。
- **助手的回复照抄当时发出的原文**，不缩写、不合并、不改写。
- **拿不到原文的那一轮写【原文不可取得】**，不用概括代替。只要有一轮缺失，完整性就标“尽可能完整版本”，并列出缺了哪几轮。
- 只有每一轮都逐字拿到了，才能标“完整”。摘要和整理稿不能冒充全文。
- 密码、授权码、密钥先遮蔽，写成 `[已遮蔽]`。
- 一个话题聊完就归档，不要拖。对话太长时，网页版 AI 往往已经拿不到前面的原文。

## 单次索引写什么

- 这场对话分了哪几个主题；
- 每个主题的关键词、结论；
- 每个结论对应全文的第几轮到第几轮；
- 用户发过图片的，用文字说明图片里是什么。

## 同一场对话再次归档：续写，不另建

同一天、同一主题、同一场连续的对话再归档时：

- **原文件还在收件箱里**：接着原来的全文和单次索引往下写，只补上次之后的轮次。新增段落前写一行这次的写入时间和执行者，并更新开头的“本次写到”。
- **原文件已经被本机取走**（收件箱里找不到了）：新建 `<原文件名去掉 .md>_续<N>.md`，开头写“接续 <原文件名>，从第 X 轮开始”，只写新的轮次。本机取回时再接到原文后面。

不要把整场对话重新写一份新文件，那样本机会出现两份内容重叠、又不完全一样的全文。

## 写完要回读核对

- 写入以后把文件读回来，核对文件名、轮数、首尾两轮是不是对的，然后才说“归档完成”，并把文件名告诉用户。
- 还没开始写就直说没写，不要说“正在处理”“稍后告诉你”。
- 写入或回读失败，说清楚失败在哪一步、哪些还没核对，不说归档完成。

## 本机怎么接回来

本机 AI 做“归档”时顺带处理收件箱：

1. **同步副仓**：`cloud.remote` 指向副仓那个同步文件夹时，跑 `python tools/cloud_sync.py run`，云端的 `inbox/<来源>/` 会落到本机的 `.personal/inbox/<来源>/`（`cloud.local_path` 默认就是 `.personal/inbox`，和飞书主资料库的 `.personal/files` 分开）。没用 `cloud_sync.py` 的，从网盘客户端或网页下载。
2. **核对**：开头几项有没有填、完整性怎么标的、轮次是否连续、`_INDEX` 文件名能不能和全文配上。有问题记进工作日志并告诉用户，不替网页版 AI 补写原话。
3. **并入**：移到 `.personal/logs/chat-exports/web/<来源>/`，文件名不改。
   - 遇到 `_续<N>` 文件：先备份本机那份全文到 `.local/backups/`，把新轮次接到全文末尾，单次索引同样处理。轮次对不上、内容重叠又不一致的，不硬接，两份都留，列给用户定。
   - 本机已有同名全文、收件箱里又来了一份同名的：比较后确认新的是旧的续写（开头一致、只多了后面的轮次）才替换，替换前先备份；否则两份都留，列给用户。
4. **更新总索引**：跑 `python tools/chat_archive.py index`（或者整套 `python tools/refresh.py`）。
5. **清收件箱**：取回、核对、并入都做完了，再清掉收件箱里已经取回的那几份，避免两边重复；没核对完的不清。用 `cloud_sync.py` 的，第 3 步把文件从 `.personal/inbox/` 挪走以后，下一次同步就会删掉云端那份，所以没核对完的先别挪；一次删得多会被删除阈值拦住，按提示处理。

连得上你私有 GitHub 仓的网页版 AI，也可以直接读本文件，不用每次手动贴下面的提示词。

## 粘给网页版 AI 的提示词

```text
以后我说“归档”，就把我们这场对话按下面的规矩存到 Google Drive（或我指定的云盘）的
「<你的副仓同步文件夹>/inbox/<来源>/」，<来源>写你自己的平台名，比如“ChatGPT网页版”：

1. 每场对话存两份普通 Markdown 文件（.md），不要存成在线文档：
   - 全文：YYYY-MM-DD_主题_来源.md
   - 单次索引：YYYY-MM-DD_主题_来源_INDEX.md（全文超过约 3000 字才写；日期、主题、来源必须和全文一模一样）
2. 全文开头写：来源平台、会话链接（没有写“待补”）、对话日期与时区、归档写入时间（YYYY-MM-DD HH:mm 加时区，用实际写入的时间）、记录执行者（实际写的是谁）、完整性（哪些轮逐字、哪些缺失）、本次写到第几轮。
3. 然后按“第 N 轮 / 用户 / 助手”逐轮写原文：
   - 我说的话逐字照抄，包括口头语、重复、说错的；
   - 你的回答照抄当时发出的原文，不缩写、不合并、不改写；
   - 确实拿不到原文的那一轮写【原文不可取得】，不要用概括代替；有任何一轮缺失，完整性就写“尽可能完整版本”并列出缺了哪几轮。
4. 密码、授权码、密钥写成 [已遮蔽]。
5. 单次索引写：分了哪几个主题，每个主题的关键词和结论，对应全文第几轮到第几轮；我发过图片的，用文字说明图片内容。
6. 同一天、同一主题、同一场连续对话再次归档时：原文件还在就接着写，只补上次之后的轮次，并更新“本次写到”；原文件已经不在收件箱了，就新建“原文件名_续N.md”，开头写“接续某某文件，从第 X 轮开始”，只写新的轮次。不要整场重写一份。
7. 不用维护对话总索引，那由我本机的脚本生成。
8. 写完把文件读回来核对文件名、轮数和首尾两轮，然后把文件名告诉我，才算完成。还没写就直说没写；失败了说清楚失败在哪一步。
9. 一个话题聊完就提醒我归档，不要等对话太长。
10. 我说的“归档本地云端”是给本机 AI 的指令，你不用管。
```

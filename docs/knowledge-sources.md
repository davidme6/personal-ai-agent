# 知识源与验证

AI 回答问题时用到的知识来自三处：你自己积累的本地知识库、网络、模型训练时学到的。三者可信度不一样，用法也不一样。本文规定先用哪个、怎么验证、本地知识库怎么越攒越多而不越攒越乱。

## 三类知识源

| 知识源 | 是什么 | 可信度 | 时效 | 用来做什么 |
|---|---|---|---|---|
| 本地知识库 | 你积累并核实过的内容（`.personal/knowledge/verified/`） | 最高 | 看维护，要定期复核 | 主力，第一优先 |
| 网络 | 外部公开信息，能查到出处 | 看来源，官方和一手资料最高 | 最新 | 查新、查证、补充 |
| 模型自带 | 模型训练时学到的 | 中低，可能过时或记错 | 停在训练时 | 解释概念、组织思路、举例 |

## 取用顺序

```text
① 本地已验证 → ② 网络上的权威来源，现查 → ③ 模型自带（标明是推断或背景）
```

1. **讲定论、讲以前定下的口径**：先用本地已验证的，保证前后一致、能追溯。
2. **涉及最新的事实、数据、会变的东西**：必须上网现查，不能只凭模型记忆。
3. **本地待验证的内容**：可以参考，核实之前不当定论讲。
4. **模型自带的知识**：用来解释和搭框架；凡是要准确数字、出处、时效的，都要落到本地或网络的来源上。
5. **几个来源说法不一致**：把分歧和各自的出处并列摆出来，不替来源做没有依据的取舍。

## 验证铁律

- **没验证的知识不写成正式结论。** 没验证的留在原始记录或 `unverified/` 里，标明状态。
- **原始对话不直接变成知识。** 聊天里说过的话，哪怕是 AI 说得很肯定的，也只是原始数据；要进知识库，先按下面的流程核实。
- **来源核验和是否掌握分开。** “这条知识对不对”看来源；“我会不会用”看学习证据（见 [学习模式](../modes/01-learning.md)）。答对了题不能证明来源可靠，来源可靠也不代表已经掌握。
- **官方材料留来源、版本和核验日期。** 文档改版、政策调整之后，旧版本的结论要重新核实。
- **个人经验先标“待核”。** 自己实践出来的结论可以记，但要写明是在什么条件下得出的，多次验证后再升级。
- **读不到就说读不到。** 文件打不开、网页取不到，直接说明，不凭印象补内容。
- **测验纠错只用于练习。** “做题 → 对答案 → 纠错 → 入库”这套流程只用在练习和测验场景，不推广成所有知识的沉淀方法。

## 本地知识库的结构

```text
.personal/knowledge/
├── 00_index.md     # 全库地图：有哪些主题、各在哪。由 AI 归档时维护
├── unverified/     # 待验证：新料先进这里，只增不改，降低记录门槛
├── verified/       # 已验证：核实通过的正式知识，按主题分目录
└── outdated/       # 过期或被证伪：从 verified 移出来的，留着追溯，不删
```

需要的话可以在 `verified/` 旁边加 `cards/`（速查卡）、`practice/`（练习题），不是必需。

### 每条知识的最小记录

```markdown
## 标题
- 主题：
- 重要程度：core（核心，严格验证）/ supporting（支撑）/ reference（参考，知道去哪查即可）
- 状态：待验证 / 已验证 / 存疑 / 过期 / 已证伪
- 来源：网址、书名和页码、官方文档名，或“自己实践”加上条件
- 版本：文档版本号或页面更新日期，没有写“未标注”
- 捕获日期：YYYY-MM-DD
- 核验日期：YYYY-MM-DD（怎么核验的：对照了哪份权威材料，或做了什么测试）
- 复核日期：YYYY-MM-DD（会变的内容才填，到期重新核实）
- 关联：相关条目的链接

内容……
```

### 从捕获到复核

1. **捕获**：看到有用的内容，先丢进 `unverified/`，文件名带日期和来源，不要求当场整理。
2. **验证**：用的时候和权威来源对照，或者实际试一次确认能用。
3. **入库**：通过了就移到 `verified/` 对应主题下，补齐来源、版本、核验日期，在 `00_index.md` 登记。
4. **提炼**（可选）：高频要记的点压成速查卡。
5. **复核**：有时效的内容到了复核日期重新核实。
6. **移出**：过期或被证伪的移到 `outdated/`，写明原因和日期；`verified/` 里引用它的地方同步改掉。

## 网络检索怎么用

1. 优先官方文档、一手资料、权威机构、经典教材、高质量的学术来源。
2. 记下网址和访问日期，写进对应的知识条目或项目证据里。
3. 搜索只用来解决“需要外部事实”的问题。学习时该自己闭卷回想的，不拿搜索代替。

## 资料归组

同一场会议、同一个主题的资料放进同一个文件夹，不散落在各处：

```text
.personal/files/<类别>/<主题>-<YYYYMMDD>/
```

例如：

```text
.personal/files/会议/季度复盘会-20260115/
├── 季度复盘会-演示文件.pptx    # ① 演示文件原件
├── 季度复盘会-逐字稿.md        # ② 逐字记录
└── 季度复盘会-纪要.md          # ③ 纪要
```

一个文件夹要有三件套，缺一件不算归组完成：

1. **演示文件原件**：会上放的幻灯片、文档。用户已经下载的就用用户的；没下载的，有权限时由 AI 下载。
2. **逐字稿**：会议软件导得出就导出；导不出、但能用工具拿到文字的，由 AI 取回存成 `.md` 或 `.txt`。
3. **纪要**：会议软件有自动纪要的，存纪要链接（写进 `纪要.md`）；没有的，由 AI 根据逐字稿写一份，开头注明“根据逐字稿整理，未经与会者确认”。

几点要求：

- 录像、演示文件、纪要链接同时存在时，主动归到一起；不要只存文字不存链接，也不要演示文件和文字分开放。
- 自动纪要里的人数、金额这类数字可能写错，以逐字稿为准。
- `.personal/files/` 走云盘，不进 Git。纪要里的结论要进知识库，照样按上面的验证规则走。

# 模式：一个底座，按任务换工作方式

同一个数字分身，有时在陪你学东西，有时在帮你做方案、跟客户，有时在修它自己。每种场景要做的事、要留下的东西、能碰的文件都不一样，但没必要为每种场景造一个互不相通的 AI。

这里的做法是：**所有场景共用一个底座，每轮先选一个模式，模式在底座上干活，需要具体方法时再调用 Skill。**

## 先分清三个概念

| 概念 | 有几个 | 是什么 | 例子 |
|---|---|---|---|
| **共享底座** | 全局一个 | 所有模式共用的规则、记忆、知识、工具和日志 | `AGENTS.md`、`.personal/`、`tools/` |
| **模式** | 4 个内置 + 你自定义的 | 一套工作预设：角色、职责、主流程、产物、读写边界 | 学习、顾问、销售、系统 |
| **Skill** | 任意多个，哪个模式都能调 | 完成某一类具体任务的方法包 | 写周报、整理会议纪要、生成报价单 |

三者的关系：模式决定“现在以什么身份、按什么流程做事、结果写到哪”；Skill 决定“这一步具体怎么做”。同一个 Skill 可以被几个模式调用，模式之间共用同一份记忆，不各存一套。

## 内置模式

| 文件 | 模式 | 什么时候进入 | 主要产物 | 主要读写位置 |
|---|---|---|---|---|
| [01-learning.md](01-learning.md) | 学习 | 学新东西、补短板、复习、自测，“这个我不懂” | 学习进度、学习证据、错题、复习队列 | `.personal/projects/<学习项目>/`、`.personal/knowledge/` |
| [02-consulting.md](02-consulting.md) | 顾问 | 诊断问题、出方案、规划小范围验证、算投入产出和风险 | 诊断结论、方案、验证计划、风险清单 | `.personal/projects/<项目>/`、`.personal/files/` |
| [03-sales.md](03-sales.md) | 销售 | 找线索、背调、沟通、出方案、跟进、复盘 | 客户档案、客户台账、跟进记录、复盘案例 | `.personal/projects/<销售项目>/` |
| [04-system.md](04-system.md) | 系统 | 改配置、改工具和 Skill、看日志、同步备份、查安全 | 配置变更、工具改动、工作日志、提交 | `config/`、`tools/`、`skill/`、`modes/`、`.personal/agent.json` |
| [00-custom-template.md](00-custom-template.md) | 自定义 | 上面几个都不贴合的新场景 | 你定义的产物 | 你定义的位置 |

为什么只内置这几个：模式要靠真实任务磨出来。凭空预设十几个空壳模式，用不上也没人维护。先把这几个跑扎实，新需求走自定义，跑稳了再转正。

## 每轮怎么定主模式

1. **先判意图，定一个主模式，再动手。** 可以借用别的模式的能力，但任何时候主模式只有一个。
2. **用户点名优先。** 用户说“切到销售模式”“用学习模式”，就按用户说的。
3. **没点名就按“什么时候进入”判断。** 判断不了，或者同时很像两个模式，用一句话把候选列出来让用户选，不要硬猜。
4. **切换要留痕。** 在本次的任务卡或工作日志里记一行：`模式：销售 → 学习，原因：报价依据不清楚，先补`。要换窗口、换设备接着做的，写进当天的交接 `.personal/handoff/YYYY-MM-DD.md`。
5. **只加载这个模式要用的东西。** 进了销售模式就读销售项目的台账和相关客户档案，不把全部记忆和所有客户资料塞进上下文。加载顺序见 [记忆系统](../docs/memory-system.md)。

## 实战模式和学习模式的互切

顾问和销售是“实战模式”，默认以推进真实的事为主，不机械地套学习流程。实战里一旦出现下面的情况，就临时切到学习模式：

- 发现自己对某个领域知识薄弱，说不清楚；
- 做出了实质性的错误判断；
- 一件事做完需要复盘；
- 需要确认自己真的掌握了某项能力。

切的方法：先把当前的业务结论冻结（写进任务卡或项目状态，标明停在哪）→ 用学习模式补齐 → 把学习证据写回 → 切回原来的模式，从冻结点继续。

这样形成一个循环：实战暴露短板 → 学习补齐 → 回到实战 → 沉淀成知识和案例 → 底座变厚。

## 权限分三档

每个模式文件里都按这三档列了动作。三档的意思全局统一：

| 档 | 意思 | 例子 |
|---|---|---|
| 直接做 | 低风险、只写本机、可追溯 | 分析、讲解、写草稿、更新自己负责的状态文件 |
| 先确认 | 会影响别人或对外 | 发消息、正式报价、提交方案、改配置、新增工具 |
| 明确授权并先备份 | 难撤回或涉及敏感数据 | 删除数据、改安全规则、处理别人的个人信息、往新的云端账号写入 |

你可以在 `.personal/profile.md` 的“Working boundaries”里改自己的边界；`profile.md` 和本文件不一致时，以 `profile.md` 和用户当轮的话为准。

## 自定义新模式

1. 复制 [00-custom-template.md](00-custom-template.md)，改名为 `NN-名字.md`（如 `05-writing.md`），按模板填写。
2. 在下面的登记表里加一行，状态写“试验”。
3. 真实用满 3 次、流程稳定能复现之后，再把状态改成“内置”，并加进上面的“内置模式”表。
4. 模式里如果写了客户、公司、个人业务这类私人细节，放到 `.personal/modes/`，不要放进本目录：本目录是公开框架的一部分，会随模板一起分享。AI 定模式时两个位置都看。
